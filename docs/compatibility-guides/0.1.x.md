# Futuruna Compatibility Guide: 0.1.x

This is the rolling compatibility guide for the current 0.1.x development line.

The formal compatibility-guide discipline starts here. Older historical changes
still live in git history, `td`, and the existing docs, but this file is now
the release-facing ledger for compatibility-impacting changes.

## Stable Surface Changes

### 2026-07-18

- Promoted the FRSS-v0 `runa from-rust` and `from-rust --verify` boundary to a
  stable, production-ready contract for deterministic single-file Rust programs
  in the documented supported subset. Category: tooling/source-translation
  compatibility. User action: users may rely on exact Rust-vs-Futuruna stdout
  matching for documented FRSS-v0 supported shapes and on stable fail-closed
  diagnostic categories for documented unsupported boundaries. Arbitrary Rust
  crate translation, Rust module-tree translation, broad macro expansion,
  generated Cargo manifests, full lifetime/reference preservation,
  unsafe/async/effectful APIs, and general iterator state-machine translation
  remain outside the stable promise unless separately promoted.
- Future FRSS-v0 support expansions must land with exact-match fixture or
  generated-lane evidence and update the evidence manifest before the contract
  claims the new source shape. Category: tooling/source-translation
  compatibility. User action: custom fixture maintainers should treat
  supported-shape removals, unsupported diagnostic category changes, and
  fixture removals as stable-surface changes unless they are documented as
  bug-fix exceptions or moved to a successor contract such as FRSS-v1.

### 2026-07-18

- Promoted the covered Rust-facing library integration contract to stable:
  `runa lib` output may be consumed as a Rust module file or as `src/lib.rs` in
  a user-owned Cargo library crate, with exported APIs at the module/crate root
  and matching Cargo dependencies supplied by the consumer. Category:
  artifact/codegen and integration compatibility. User action: Rust consumers
  relying on generated Futuruna libraries should use one of the documented
  layouts; automatic manifest generation, private helper layout, richer FFI
  patterns, and `runa from-rust` remain outside this stable promise.
- `runa lib` now emits dependency guidance when generated Rust requires external
  Cargo crates: the generated source header and stderr list Cargo.toml-ready
  dependency entries. Category: artifact/codegen and integration compatibility.
  User action: copy the listed entries into the consuming crate's
  `[dependencies]` before compiling the generated library source.
- Documented the stable first-run contract for `runa init`, `check`,
  `fmt --check`, `run`, `build`, and tutorial 01 examples; `./scripts/mint.sh`
  keeps that path blocking through the first-run canary. Category: CLI and
  onboarding compatibility. User action: none for ordinary use; contributors
  should update the contract when changing first-run behavior.
- Added Futuruna-level diagnostics for simple first-hour type mistakes before
  Rust codegen: annotated literal mismatches, heterogeneous list literals, and
  literal `if` branch mismatches now fail in `runa check` with stable
  expectation coverage. Category: diagnostic compatibility. User action:
  expect these cases to report Futuruna diagnostics instead of Rust compiler
  errors.

### 2026-07-18

- Promoted pure/core generated Rust behavior and reviewed artifact fixtures from
  preview to stable. Category: artifact/codegen compatibility. User action:
  none for ordinary programs; exact helper names, private generated layout,
  Rust interop, `runa lib`, and WASM package shape remain outside this stable
  promise unless covered by a named fixture or explicit doc.
- Promoted Rust formatting and repository hygiene to production-ready in the
  scorecard after repo-wide `cargo fmt --check` parity and routine `runa fmt`
  gates were established. Category: tooling/process compatibility. User action:
  contributors should keep formatting-only churn separate from semantic changes.
- Promoted streams, subjects, actors, and effect-heavy workflows from preview to
  stable/production-ready. Category: reactive/stateful language compatibility.
  User action: live stream consumption must continue to use explicit named
  scope ownership; generic live-async roundtrip/check-codegen skips are explicit
  skip accounting, not evidence of parity.
- Promoted differential/generative compiler testing and `runa stress-gen` from
  preview to stable/production-ready as a quality-gate surface. Category:
  tooling/process compatibility. User action: contributors should treat
  `./scripts/differential.sh` as the canonical differential lane, keep saved
  failures replayable, and land future compiler bugs in the narrowest permanent
  corpus, expectation, canary, or downstream fixture.

### 2026-07-18

- Added a pull-request compatibility-guide check for tracked stable-surface
  files. Category: contributor and release-process compatibility. User action:
  changes that touch stable surfaces must update this guide or fill the PR
  template reason explaining why no guide entry is needed.

### 2026-07-18

- Published the formal compatibility contract in
  [../compatibility-policy.md](../compatibility-policy.md) and surfaced current
  stage assignments in [../feature-stages.md](../feature-stages.md).
  Category: source of truth for source/behavioral/verification/artifact
  classification. User action: none, but future release-facing compatibility
  changes should now reference this guide.

## Bug-Fix Exceptions

### 2026-07-18 Rust use declarations

- Preserved root-level `@ use` declarations through Rust codegen declaration
  scanning so `runa lib` and compiled output emit the documented Rust imports.
  Category: artifact/codegen compatibility. Reason: dropping root `@ use`
  contradicted the documented Rust interop contract; duplicate imports for
  Futuruna's generated collection prelude are suppressed so existing programs
  such as `@ use std::collections::HashMap` keep compiling.

### 2026-07-18 Unicode string semantics

- Defined `string_length`, `length` on `String`, `substring`, `char_at`, and
  `index_of` over Unicode scalar values. Category: behavioral compatibility.
  Reason: byte-count length was an accidental shortcut while `substring` and
  `char_at` already used scalar positions; keeping mixed index spaces made
  ordinary non-ASCII string processing unreliable.

### 2026-07-18 hardening wave

- Restored `substring(s, start, length)` to the documented length-based
  contract after compiled behavior drifted. Category: behavioral compatibility.
  Reason: the previous compiled behavior contradicted the documented language
  contract and was treated as a bug-fix exception rather than a supported
  alternative.
- Aligned map/set and collection-entry semantics toward deterministic behavior
  across interpreter and compiled execution. Category: behavioral
  compatibility. Reason: nondeterministic or inconsistent collection behavior
  was treated as too wrong to preserve.
- Aligned partial builtin runtime contracts such as list indexing and
  `head([])` across runtimes. Category: behavioral compatibility. Reason: the
  previous mismatch was not a supported compatibility mode; it was a bug or
  unspecified edge that needed an explicit single contract.
- Fixed imported-library and top-level visibility/codegen failures for nested
  imports, imported smoke leakage, and downstream consumer compilation paths.
  Category: source and behavioral compatibility. Reason: compiled behavior was
  incorrect for valid user programs and was treated as wrong-code / broken
  resolution rather than a supported old behavior.
- Promoted importable local libraries, downstream consumer shape, and
  `runa lint-library` import hygiene to stable/production-ready. Category:
  source, behavioral, and tooling compatibility. User action: reusable helper
  files that claim the stable importable-library contract should be marked with
  `-- library-hygiene: importable` and kept green under
  `runa lint-library --imports`.

## Preview And Experimental Notes

### 2026-07-18

- `runa from-rust` moved from experimental to preview for the checked
  single-file validation boundary documented in
  [../from-rust-contract.md](../from-rust-contract.md). Category: tooling stage
  promotion. User action: do not treat this as arbitrary Rust crate
  translation; supported fixtures still need exact stdout parity and
  unsupported shapes still need explicit fail-closed directives.
- The preview `runa from-rust` boundary is now named FRSS-v0, the From-Rust
  Single-File Supported Subset version 0, with category, unsupported-boundary,
  lane-mapping, and preview compatibility-policy sections in
  [../from-rust-contract.md](../from-rust-contract.md). Category:
  preview-tooling contract clarification. User action: use FRSS-v0 to reason
  about supported single-file Rust inputs; arbitrary crate translation remains
  outside the claim.
- `runa from-rust --verify` now emits stable uncolored summary lines for FRSS-v0
  supported matches, recognized unsupported categories, Rust parse/compile/run
  failures, translated Futuruna parse failures, and output divergence, while
  keeping colored transpiled-source and diff output as diagnostic display.
  Category: preview-tooling output hardening. User action: scripts should key
  off `from-rust verify: ...` summary lines instead of colored diagnostic
  headings.
- `runa from-rust` unsupported checked-in Rust shapes now fail closed with
  stable diagnostic categories instead of flowing into Futuruna parse failures
  or wrong translated output. Category: preview-tooling diagnostic hardening.
  User action: fixtures that rely on
  unsupported Rust features should use the top-of-file
  `// runa-from-rust: expect-unsupported ...` directive; supported fixtures
  without that directive must continue to match Rust stdout exactly.
- `runa from-rust` now treats unproven control/assertion macros such as
  `panic!`, `todo!`, `unimplemented!`, `assert!`, and `assert_eq!` as
  `unsupported-macro` instead of letting them reach translated Futuruna parse
  failures or non-equivalent output. Category: preview-tooling diagnostic
  hardening. User action: keep these macros in expected-unsupported fixtures
  unless a future FRSS contract promotes them with exact Rust/Futuruna stdout
  evidence.
- `runa from-rust` now fails closed on effectful `std` APIs outside FRSS-v0's
  deterministic pure/core boundary, including file I/O, environment/process
  state, process control, runtime I/O, networking, wall-clock time, and
  randomized hashing through `RandomState`. Category: preview-tooling
  diagnostic hardening. User action: keep these shapes in
  expected-unsupported fixtures unless and until a separate effectful contract
  is promoted.
- `runa from-rust` now fails closed on Rust `mod` declarations, including
  external `mod helper;` files and inline `mod helper { ... }` blocks, because
  FRSS-v0 is a flat single-file validation boundary rather than a Rust module
  tree translator. Category: preview-tooling diagnostic hardening. User action:
  keep Rust module boundaries out of supported FRSS-v0 fixtures unless a future
  contract version promotes them with exact-match evidence.
- `./scripts/from-rust-differential.sh` now uses a checked-in FRSS-v0
  source-shape-family search manifest and three default stable seeds, raising
  the default generated exact-match lane from 6 to 24 cases while keeping replay
  and minimization artifacts on failure. Category: preview-tooling evidence
  hardening. User action: none unless maintaining custom tooling that asserts
  the old `From-rust: 6 matched` summary; such tooling should read the script's
  expected summary or artifact `coverage.tsv` instead.
- The preview `runa from-rust` supported subset now includes the checked-in
  rich `Result` integer parse-error chain shape: `s.parse().map_err(...)?` plus
  early `return Err(...)` guards. Category: preview-tooling support expansion.
  User action: none for existing expected-unsupported fixtures;
  remove the directive when promoting a fixture into exact Rust/Futuruna stdout
  matching.
- The preview `runa from-rust` supported subset now includes the checked-in
  generic trait shape used by `examples/from-rust/adversarial_2_generics.rs`:
  the narrow `Functor` associated-type pattern for `Option` and `Result`,
  generic higher-order functions, `impl Fn` composition, generic struct
  constructors, and generic inherent methods. Category: preview-tooling support
  expansion. User action: none unless maintaining expected-unsupported
  from-rust fixtures; associated-type and `impl Trait` shapes outside this
  checked subset still fail closed as `associated-types` or `impl-trait`.
- The preview `runa from-rust` supported subset now includes the checked-in
  nested pattern shape used by `examples/from-rust/adversarial_5_patterns.rs`:
  recursive `Box<T>` enum constructors plus ordered two-reference tuple matches
  lowered to nested Futuruna matches. Category: preview-tooling support
  expansion. User action: none unless maintaining expected-unsupported
  from-rust fixtures; tuple-reference match shapes outside this checked subset
  still fail closed as `reference-tuple-match`.
- The preview `runa from-rust` validation lane now includes
  consumer-shaped single-file fixtures for config parsing/validation, invoice
  totals, and event rollups. Category: preview-tooling corpus expansion.
  User action: none; this documents the current validation boundary and does
  not freeze arbitrary Rust crate translation.
- The preview `runa from-rust` supported subset now includes the checked-in
  recursive ownership shape used by
  `examples/from-rust/adversarial_1_ownership.rs`: `Vec<Box<T>>` owned trees,
  inherent impl method calls, functional `&mut self` field-push lowering, and
  the narrow recursive `Option<&T>` search pattern translated as value
  `Option(T)`. Category: preview-tooling support expansion. User action:
  none unless maintaining expected-unsupported from-rust fixtures; borrowed
  return-reference shapes outside this checked subset still fail closed as
  `borrowed-return-reference`.
- The preview `runa from-rust` supported subset now includes the checked-in
  stateful iterator/map grouping shape used by
  `examples/from-rust/adversarial_4_closures.rs`: tuple-key `sort_by`,
  Fibonacci-style `scan(...).collect()`, Rust debug formatting for promoted
  `{:?}` prints, and `entry(...).or_insert_with(Vec::new).push(...)` lowering.
  Category: preview-tooling support expansion. User action: none unless
  maintaining expected-unsupported from-rust fixtures; unsupported iterator
  shapes outside this subset still fail closed as `stateful-iterator-chain`.
