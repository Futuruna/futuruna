# Futuruna Compatibility Guide: 0.1.x

This is the rolling compatibility guide for the current 0.1.x development line.

The formal compatibility-guide discipline starts here. Older historical changes
still live in git history, `td`, and the existing docs, but this file is now
the release-facing ledger for compatibility-impacting changes.

## Stable Surface Changes

### 2026-07-18

- Added a pull-request compatibility-guide check for tracked stable-surface
  files. Category: contributor and release-process compatibility. User action:
  changes that touch stable surfaces must update this guide or fill the PR
  template reason explaining why no guide entry is needed.

### 2026-07-18

- Published the formal compatibility contract in
  [../compatibility-policy.md](../compatibility-policy.md) and surfaced current
  stage assignments in [../feature-stages.md](../feature-stages.md).
  Category: source of truth for source/behavioral/verification/artifact

  changes should now reference this guide.

## Deprecations

None recorded yet for the 0.1.x guide line.

## Bug-Fix Exceptions

### 2026-07-18 Unicode string semantics

- Defined `string_length`, `length` on `String`, `substring`, `char_at`, and
  `index_of` over Unicode scalar values. Category: behavioral compatibility.
  Reason: byte-count length was an accidental shortcut while `substring` and
  `char_at` already used scalar positions; keeping mixed index spaces made
  ordinary non-ASCII string processing unreliable.

### 2026-07-18 hardening wave

- Restored `substring(s, start, length)` to the documented length-based
  contract after compiled behavior drifted. Category: behavioral compatibility.
  Reason: the previous compiled behavior contradicted the documented language
  contract and was treated as a bug-fix exception rather than a supported
  alternative.
- Aligned map/set and collection-entry semantics toward deterministic behavior
  across interpreter and compiled execution. Category: behavioral
  compatibility. Reason: nondeterministic or inconsistent collection behavior
  was treated as too wrong to preserve.
- Aligned partial builtin runtime contracts such as list indexing and
  `head([])` across runtimes. Category: behavioral compatibility. Reason: the
  previous mismatch was not a supported compatibility mode; it was a bug or
  unspecified edge that needed an explicit single contract.
- Fixed imported-library and top-level visibility/codegen failures for nested
  imports, imported smoke leakage, and downstream consumer compilation paths.
  Category: source and behavioral compatibility. Reason: compiled behavior was
  incorrect for valid user programs and was treated as wrong-code / broken
  resolution rather than a supported old behavior.
