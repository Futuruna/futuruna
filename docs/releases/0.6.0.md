# Futuruna 0.6.0

Futuruna 0.6.0 says who answers a fact. A partial case says which facts are
missing; an **`AnswerGuide`**, written by the integrator and not by the law,
maps input paths to the integrator's own groups of resolvers. Every path it
does not name is held: the integrator builds it into every case, and a need
there is a defect in its data. `answer(entry, case, guide, resolve)` asks an
entry round by round and calls each group's resolver once per round with all
of its needs; `runa call --guides FILE --guide NAME` gives each need of a
partial call its group as `"by"`; and the generated TypeScript SDK answers an
entry by its guide, with one resolver per group, from a shared runtime package
`@futuruna/runtime`. `@ calculate` is now `@ entry`, the wire ids are
`futuruna.entry.*`, and `interview` is `answer`.

0.6.0 breaks models and readers written for 0.5: `@ calculate` no longer
parses, `interview` and `Interview` are gone, and every contract's schema id
and hash change. `runa fmt --migrate` rewrites most of it; read
[Compatibility](#compatibility) before upgrading. Everything new in this
release is Experimental.

## Answering an entry (Experimental)

```runa
-- household.guide.runa
@ import ./household.entry

# Origin = Registry | Customer

= household_guide = AnswerGuide(fields = [
    EntryField(path = pathof(Household::spouse), by = Customer),
    EntryField(path = pathof(Household::children::age), by = Registry)
])

= answered = answer(household_tax, started, household_guide, from_case(complete))
```

- **The guide.** `AnswerGuide(i, g)` holds `EntryField(path, by)` items: a
  `pathof` path of the entry's input `i` and a group, a constructor without
  fields of the integrator's group type `g`. A named path covers what is
  below it unless a more specific item names a path below; list indices are
  not written, and the alternative of a sum type is named. `pathof(T)` is the
  whole input. A group is written as any constructor (`Origin.Customer` where
  two group types declare `Customer`), and is its bare name in `"by"`.
- **Held and named.** A path the guide does not name is held. A named path
  may be missing; the case carries it whenever the integrator has it, and the
  group is asked only for what is missing.
- **`answer`** asks the entry as `query` does (with the strict-mode oracle
  and the completion test under `runa test`). A need at a held path stops the
  program with an error naming the path, the guide and the round. Each group
  that has needs is called once per round with all of them; an answer for a
  path the group was not asked is an error; answers are written with `fill`.
  The result is `Answering(rounds, outcome)`: each `Round` lists the needs'
  paths and what each group was asked, and the outcome is `Answered(result)`
  or, when a round answers nothing, `Unanswered(open, case)`.
- **`from_case(complete)` and `whole_case_guide()`** answer a case from a
  complete one, as `interview` did.
- **Where a guide lives.** A guide is a top-level binding of a ground value,
  so `runa check`, `runa call --guide` and `runa sdk ts --guide` read it
  without running the program. A guide in a file that declares an `@ entry`,
  or in a file such a file imports, is a check error, and so is `answer`
  reached from an entry.
- **Checks.** `runa check` reports a guide that is not ground or names no
  path, a path with a list index, paths into two input types, a path named
  twice, a group with fields, groups of two types, a group type that is not a
  plain sum, a group constructor with no path, `answer` of a name that is not
  an entry or with a guide rooted at another type, and, as a warning, an item
  that resolves nothing because every path below it is named more
  specifically.
- **Interpreter only.** A guide, like a `query`, runs in the interpreter:
  `runa check` checks the frontend of a file of guides and reports
  `interpreted (guide)`, and `runa build` and `runa run` refuse it.
- **`runa call --guides FILE --guide NAME`** checks `FILE`, takes its guide
  `NAME` (rooted at the entry's input type), and gives each need and each
  `later` need of a partial call `"by": "<Group>"`. A need at a held path has
  no `by` and is a diagnostic of its case. The contract, the template and the
  schema hash do not change; the partial-result schema documents `by`.

See [Answering an entry](../reference/calculations.md#answering-an-entry) and
the [AnswerGuide RFC](../rfcs/answer-guide.md).

## TypeScript SDK (Experimental)

- **Answering by a guide.** `runa sdk ts FILE --out DIR --guides G --guide entry=guide`
  writes `answer.ts`: the guide's groups (`<Entry>Group`), the held case type
  `<Entry>Held` (every held fact's key required; `undefined` means not known),
  the resolvers `<Entry>Resolvers` (one per group, every group required) and
  `<entry>Answer(transport, held, resolvers)`. Each group's resolver is called
  once per round with all of its needs, each carrying `by`; resolvers reply
  with `given(need, value)` or `open`, and `leaveOpen` names a group nobody can
  fill yet. A run ends `Answered`, or `Unanswered` with `open` keyed by group;
  a need at a held path throws `HeldMissingError`.
- **Removed:** pattern-keyed `resolve()`, `Resolvers`, `answer()`, `ask`,
  `ResolveError`/`ResolveCycleError` (now `AnswerError`/`AnswerCycleError`) and
  `--runtime`. Without `--guide` the SDK has the calls and queries only.
- **`@futuruna/runtime`** is its own npm package, imported by generated SDKs.
  `runa sdk runtime --out DIR` writes it at Futuruna's version with `zod` 4 as
  a peer dependency; each release attaches `futuruna-runtime-<version>.tgz`.
- **Unit converters.** A unit whose scale is built from 2s and 5s
  (`= DKK / 100`) gets exact integer `øre.fromDecimal("1740.25")` and
  `øre.toDecimal(x)`; an amount finer than the unit throws a `CalculationError`
  of kind `amount` naming the unit and the amount.

## `@ entry`

`@ entry` and `@ entry("title")` mark an entry; `@ calculate` is a parse
error that names `@ entry` and `runa fmt --migrate`. The contract's ids are
`futuruna.entry.v1`, `futuruna.entry.input.v2`, `futuruna.entry.output.v1`
and `futuruna.entry.partial-output.v1`; `PreparedCalculation` is
`PreparedEntry`; messages, help and documentation say "entry". Entry files
are called `*.entry.runa` by convention.

## The TypeScript SDK answers by a guide (Experimental)

```sh
runa sdk ts household.entry.runa --out sdk \
  --guides household.guide.runa --guide household_tax=household_guide
```

```ts
const held: HouseholdTaxHeld = { income: 500, married: true, children: [{ name: "Ada" }] };
const resolvers: HouseholdTaxResolvers = {
  Registry: async (needs) => {
    const ages = await registry.ages(needs.map((need) => need.path));
    return (need) => {
      const age = ages.get(need.path);
      return age === undefined ? open : given(need, age);
    };
  },
  Customer: leaveOpen,
};
const answering = await householdTaxAnswer(transport, held, resolvers);
```

- **`answer.ts`.** With `--guides FILE --guide entry=guide`, `runa sdk ts`
  checks the guides file as `runa check` does, reads the guide without
  running it and writes a sixth module. For each entry given a guide it holds
  the groups, the patterns of each group, the held case type, the resolvers
  by group, the guide's table and `<entry>Answer`. Without `--guide`, the SDK
  has the calls and queries only.
- **The held case** (`<Entry>Held`). The key of every fact the guide does not
  name is required, and its value is the model's type: leaving a held fact
  out, giving it as `undefined`, or not giving a fact the model adds does not
  compile. An optional fact may be `none` where the model allows it. A
  builder whose source may lack a value decides there what a missing value
  means. A fact the guide resolves may be left out or given when known.
- **Resolvers by group** (`<Entry>Resolvers`). Every group is required. A
  resolver is called once per round with all of that round's needs of its
  group, typed by the group's patterns, and returns the function that answers
  each need: `given(need, value)`, `open`, or another entry's outcome through
  `context.runEntry`. A reply for a path the resolver was not asked throws
  `AnswerError`. `leaveOpen` is the resolver of a group nobody can fill yet.
- **`<entry>Answer(transport, held, resolvers)`** queries through
  `transport.callPartial`, attaches each need's group as `by` from the
  generated table, writes the answers and queries again. It ends `Answered`
  with the result, or `Unanswered` with the last round's needs keyed by the
  group that left them open and the partial case. A need at a held path throws
  `HeldMissingError` before any resolver runs; with the held type that can
  only come from data the types do not see, such as an `as` cast. A cycle of
  entries throws `AnswerCycleError`.
- **Unit converters.** A unit whose scale is a finite decimal of its base
  (`# unit Ore "DKK øre" = DKK / 100`) gets `ore.fromDecimal("1740.25")` and
  `ore.toDecimal(x)`, in integer arithmetic. An amount finer than one unit,
  text that is not a decimal number, or a result beyond a safe integer throws
  a `CalculationError` of kind `amount`.
- **`@futuruna/runtime`.** What every SDK shares (validators, codecs, paths,
  needs, calls, answering, converters, error classes) is one package that
  depends on no model, with `zod` 4 as a peer dependency. `runa sdk runtime
  --out DIR` writes it at `runa`'s version, and the release attaches it as
  `futuruna-runtime-0.6.0.tgz`. A model package depends on it from the
  release URL, or vendored:

  ```sh
  runa sdk runtime --out build/runtime
  mkdir -p vendor && npm pack ./build/runtime --pack-destination vendor
  npm install ./vendor/futuruna-runtime-0.6.0.tgz
  ```

See [Answering by a guide](../reference/calculations.md#answering-by-a-guide)
and [The runtime package](../reference/calculations.md#the-runtime-package).

## Fixed

- **`sort` on a partial case no longer panics.** In 0.5.0, a partial case
  whose sort key was unknown (a left-out `account_id` of an event sorted by
  account) could stop the call with "internal runtime failure during
  calculation": the comparator treated an unknown as equal to every value,
  which is not a total order, and Rust's sort panicked once the list was long
  enough. An unknown now orders before every known value and equal to other
  unknowns. The key is still read, so the sorted list is unknown and the key
  becomes a need. `sort_by`, `list_min` and `list_max` share the comparator.
- **A file of guides passes `runa check`.** It is interpreted only, as a
  query is, instead of failing in generated Rust that has no `Path`.

## Compatibility

- `@ calculate` → `@ entry`: `runa fmt --migrate` rewrites it.
- `interview(|c| query e(c), partial, complete)` → `answer(e, partial,
  whole_case_guide(), from_case(complete))`; `x.rounds` →
  `map(x.rounds, |r| r.paths)`; `x.result == v` → `x.outcome == Answered(result
  = v)`. `runa fmt --migrate` rewrites these and lists every other use of
  `interview` or `Interview` with its line.
- Every contract's schema id is `futuruna.entry.*` (was `futuruna.calculate.*`)
  and every schema hash changes. Regenerate templates and stored hashes; a 0.5
  input envelope with a 0.5 hash is refused as any stale hash is.
- Rust API: `PreparedCalculation` is `PreparedEntry`.
- Entry files are named `*.entry.runa` by convention, not `*.calculate.runa`;
  `runa` reads either name, so renaming is optional.
- A JSON need may carry `by` (only with `--guide`).
- TypeScript SDK: the pattern-keyed `resolve()` and `Resolvers`, the reply
  helpers `answer(need, value)` and `ask`, and `Resolution` are gone; answer
  with `--guide` and `<entry>Answer`, replying `given(need, value)` or `open`. `runa sdk ts
  --runtime` and the generated `runtime.ts` are gone; install
  `@futuruna/runtime` at the version of the `runa` that generates the SDK.
  Regenerate every SDK.

## Known limitations

- A guide is read statically: its items must be written out in the binding,
  not computed.
- `later` needs get `by` but are not batched or answered until a round makes
  them needs.
- A guide is interpreted only; native code has no guides.
- A unit cannot declare a rounding policy yet; generated converters refuse
  an amount finer than one unit.
- The SDK's held type checks what TypeScript sees; data that reaches
  `<entry>Answer` untyped or through a cast is checked only at run time.
- `@ field(at = pathof(…), label, help)`, the RFC's use-site label, is not in
  this release; a use-site label stays an `@ meta` record naming its field by
  `pathof`.
