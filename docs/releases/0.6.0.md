# Futuruna 0.6.0

Futuruna 0.6.0 says who answers a fact. A partial case says which facts are
missing; an **`AnswerGuide`**, written by the integrator and not by the law,
maps input paths to the integrator's own groups of resolvers. Every path it
does not name is held: the integrator builds it into every case, and a need
there is a defect in its data. `answer(entry, case, guide, resolve)` asks an
entry round by round and calls each group's resolver once per round with all
of its needs; `runa call --guides FILE --guide NAME` gives each need of a
partial call its group as `"by"`. `@ calculate` is now `@ entry`, the wire
ids are `futuruna.entry.*`, and `interview` is `answer`.

0.6.0 breaks models and readers written for 0.5: `@ calculate` no longer
parses, `interview` and `Interview` are gone, and every contract's schema id
and hash change. `runa fmt --migrate` rewrites most of it; read
[Compatibility](#compatibility) before upgrading. Everything new in this
release is Experimental.

## Answering an entry (Experimental)

```runa
-- household.guide.runa
@ import ./household.entry

# Origin = Registry | Customer

= household_guide = AnswerGuide(fields = [
    EntryField(path = pathof(Household::spouse), by = Customer),
    EntryField(path = pathof(Household::children::age), by = Registry)
])

= answered = answer(household_tax, started, household_guide, from_case(complete))
```

- **The guide.** `AnswerGuide(i, g)` holds `EntryField(path, by)` items: a
  `pathof` path of the entry's input `i` and a group, a constructor without
  fields of the integrator's group type `g`. A named path covers what is
  below it unless a more specific item names a path below; list indices are
  not written, and the alternative of a sum type is named. `pathof(T)` is the
  whole input.
- **Held and named.** A path the guide does not name is held. A named path
  may be missing; the case carries it whenever the integrator has it, and the
  group is asked only for what is missing.
- **`answer`** asks the entry as `query` does (with the strict-mode oracle
  and the completion test under `runa test`). A need at a held path stops the
  program with an error naming the path, the guide and the round. Each group
  that has needs is called once per round with all of them; an answer for a
  path the group was not asked is an error; answers are written with `fill`.
  The result is `Answering(rounds, outcome)`: each `Round` lists the needs'
  paths and what each group was asked, and the outcome is `Answered(result)`
  or, when a round answers nothing, `Unanswered(open, case)`.
- **`from_case(complete)` and `whole_case_guide()`** answer a case from a
  complete one, as `interview` did.
- **Where a guide lives.** A guide is a top-level binding of a ground value,
  so `runa check`, `runa call --guide` and `runa sdk ts --guide` read it
  without running the program. A guide in a file that declares an `@ entry`,
  or in a file such a file imports, is a check error, and so is `answer`
  reached from an entry.
- **Checks.** `runa check` reports a guide that is not ground or names no
  path, a path with a list index, paths into two input types, a path named
  twice, a group with fields, groups of two types, a group type that is not a
  plain sum, a group constructor with no path, `answer` of a name that is not
  an entry or with a guide rooted at another type, and, as a warning, an item
  that resolves nothing because every path below it is named more
  specifically.
- **Interpreter only.** A guide, like a `query`, runs in the interpreter:
  `runa check` checks the frontend of a file of guides and reports
  `interpreted (guide)`, and `runa build` and `runa run` refuse it.
- **`runa call --guides FILE --guide NAME`** checks `FILE`, takes its guide
  `NAME` (rooted at the entry's input type), and gives each need and each
  `later` need of a partial call `"by": "<Group>"`. A need at a held path has
  no `by` and is a diagnostic of its case. The contract, the template and the
  schema hash do not change; the partial-result schema documents `by`.

See [Answering an entry](../reference/calculations.md#answering-an-entry) and
the [AnswerGuide RFC](../rfcs/answer-guide.md).

## `@ entry`

`@ entry` and `@ entry("title")` mark an entry; `@ calculate` is a parse
error that names `@ entry` and `runa fmt --migrate`. The contract's ids are
`futuruna.entry.v1`, `futuruna.entry.input.v2`, `futuruna.entry.output.v1`
and `futuruna.entry.partial-output.v1`; `PreparedCalculation` is
`PreparedEntry`; messages, help and documentation say "entry". Entry files
are called `*.entry.runa` by convention.

## Fixed

- **`sort` on a partial case no longer panics.** In 0.5.0, a partial case
  whose sort key was unknown (a left-out `account_id` of an event sorted by
  account) could stop the call with "internal runtime failure during
  calculation": the comparator treated an unknown as equal to every value,
  which is not a total order, and Rust's sort panicked once the list was long
  enough. An unknown now orders before every known value and equal to other
  unknowns. The key is still read, so the sorted list is unknown and the key
  becomes a need. `sort_by`, `list_min` and `list_max` share the comparator.
- **A file of guides passes `runa check`.** It is interpreted only, as a
  query is, instead of failing in generated Rust that has no `Path`.

## Compatibility

- `@ calculate` → `@ entry`: `runa fmt --migrate` rewrites it.
- `interview(|c| query e(c), partial, complete)` → `answer(e, partial,
  whole_case_guide(), from_case(complete))`; `x.rounds` →
  `map(x.rounds, |r| r.paths)`; `x.result == v` → `x.outcome == Answered(result
  = v)`. `runa fmt --migrate` rewrites these and lists every other use of
  `interview` or `Interview` with its line.
- Every contract's schema id is `futuruna.entry.*` and every schema hash
  changes. Regenerate templates and stored hashes; a 0.5 input envelope with a
  0.5 hash is refused as any stale hash is.
- A JSON need may carry `by` (only with `--guide`).

## Known limitations

- A guide is read statically: its items must be written out in the binding,
  not computed.
- `later` needs get `by` but are not batched or answered until a round makes
  them needs.
- A guide is interpreted only; native code has no guides.
- Unit scales and the policy for amounts finer than a unit cannot be declared
  yet; generated converters refuse finer amounts.
