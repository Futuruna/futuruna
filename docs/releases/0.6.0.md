# Futuruna 0.6.0

Futuruna 0.6.0 generates, for every entry, its **AnswerGuide**: from the law,
one item for every input path pattern at which a need can arise, with its
type and the law's metadata (label, question, help, unit, key fields,
sources). The integrator writes only the mapping of its data into a case and
one `resolve`; which source answers which need stays in its own code, built
from the guide. `answer(entry, case, resolve)` asks an entry round by round
and calls `resolve` once per round with all of that round's needs, and the
generated TypeScript SDK does the same for every entry (`<entry>Answer`,
with the guide as `<entry>Guide`), from a shared runtime package
`@futuruna/runtime`.
`@ calculate` is now `@ entry`, the wire ids are `futuruna.entry.*`, and
`interview` is `answer`.

0.6.0 breaks models and readers written for 0.5: `@ calculate` no longer
parses, `interview` and `Interview` are gone, and every contract's schema id
and hash change. `runa fmt --migrate` rewrites most of it; read
[Compatibility](#compatibility) before upgrading. Everything new in this
release is Experimental.

## Every entry generates its AnswerGuide (Experimental)

- **`answer_guide(entry)`** returns `AnswerGuide(entry, needs)`: a
  `GuideNeed(pattern, kind, value_type, label, question, help, unit, keys,
  sources, entry, subject)` for every pattern at which the entry can need a
  fact or another entry. It is derived from the contract, interpreter only
  like `query`; the engine, its JSON and the WebAssembly build are unchanged.
- **The SDK** exports it as `<entry>Guide: AnswerGuide<<Entry>Need["pattern"]>`,
  keyed by need pattern and complete over the entry's `Need` union: data for
  documentation, forms and the integrator's routing.
- The guide says nothing about the integrator: no groups, no sources of its
  own. Routing a need to the customer, another bank or the back office is the
  integrator's code.

See [The generated AnswerGuide](../reference/calculations.md#the-generated-answerguide).

## Answering an entry (Experimental)

```runa
@ import ./household.entry

= answered = answer(household_tax, started, from_case(complete))

> nobody(needs: List(Need(Household)), case: Household) -> Answers(Household) {
    Answers(from = case, given = [])
}
= stuck = answer(household_tax, started, nobody)
```

- **`answer(e, case, resolve)`** asks the `@ entry` `e` as `query` does (with
  the strict-mode oracle and the completion test under `runa test`). Each
  round it calls `resolve(needs, case)` once with all of the round's needs;
  `resolve` returns `Answers(from, given)`, the paths it answers and a case
  holding their values. Answering a path that was not asked is an error;
  answers are written with `fill`.
- **The result** is `Answering(rounds, outcome)`: each `Round(paths, given)`
  lists the paths asked and the paths answered, so a test states the rounds,
  and the outcome is `Answered(result)` or, when a round answers nothing,
  `Unanswered(open, case)` with that round's needs and the case as far as it
  got.
- **`from_case(complete)`** is the test oracle: it answers every need from a
  complete case, as `interview` did.
- **Interpreter only.** `answer`, like `query`, runs in the interpreter;
  `runa build` and `runa run` refuse it, and `runa check` reports `answer` of
  a name that is not an entry and `answer` reached from an entry.

See [Answering an entry](../reference/calculations.md#answering-an-entry).

## `@ entry`

`@ entry` and `@ entry("title")` mark an entry; `@ calculate` is a parse
error that names `@ entry` and `runa fmt --migrate`. The contract's ids are
`futuruna.entry.v1`, `futuruna.entry.input.v2`, `futuruna.entry.output.v1`
and `futuruna.entry.partial-output.v1`; `PreparedCalculation` is
`PreparedEntry`; messages, help and documentation say "entry". Entry files
are called `*.entry.runa` by convention.

## The TypeScript SDK answers an entry (Experimental)

```sh
runa sdk ts household.entry.runa --out sdk
```

```ts
const resolve: HouseholdTaxResolve = async (needs) => {
  const ages = await registry.ages(needs.filter((n) => n.pattern === "children[].age").map((n) => n.path));
  return (need) => {
    switch (need.pattern) {
      case "children[].age": {
        const age = ages.get(need.path);
        return age === undefined ? open : given(need, age);
      }
      default:
        return open;
    }
  };
};
const answering = await householdTaxAnswer(transport, started, resolve);
```

- **`<entry>Answer(transport, partialCase, resolve)`** for every entry, in
  `client.ts`, with its resolve type `<Entry>Resolve`. It queries through
  `transport.callPartial`, calls `resolve` once per round with all of the
  round's needs, writes the answers and queries again.
- **Typed replies.** `resolve` returns the function that answers each need:
  `given(need, value)`, its value typed by the need's pattern, `open`, or
  another entry's outcome through `context.runEntry`. The need pattern union
  is generated, so a `switch (need.pattern)` is exhaustive. A reply for a path
  that was not asked throws `AnswerError`; a cycle of entries throws
  `AnswerCycleError`.
- **The outcome.** A run ends `Answered` with the result, or `Unanswered` with
  `open` (the last round's needs), `pending` entry needs, `later` facts, the
  partial case and the rounds (`{ paths, given }`).
- **Needs with law metadata.** Each need carries its label, question, help,
  unit, sources, `keys` and `waiting`, so the integrator routes it to a source
  in its own code.
- **Removed:** the 0.5 pattern-keyed `resolve()`, `Resolvers`, `answer()`,
  `ask`, `Resolution`, `ResolveError`/`ResolveCycleError` (now
  `AnswerError`/`AnswerCycleError`) and `--runtime`.
- **Unit converters.** A unit whose scale is a finite decimal of its base
  (`# unit Ore "DKK øre" = DKK / 100`) gets `ore.fromDecimal("1740.25")` and
  `ore.toDecimal(x)`, in integer arithmetic. An amount finer than one unit,
  text that is not a decimal number, or a result beyond a safe integer throws
  a `CalculationError` of kind `amount`.
- **`@futuruna/runtime`.** What every SDK shares (validators, codecs, paths,
  needs, calls, answering, converters, error classes) is one package that
  depends on no model, with `zod` 4 as a peer dependency. `runa sdk runtime
  --out DIR` writes it at `runa`'s version, and the release attaches it as
  `futuruna-runtime-0.6.0.tgz`. A model package depends on it from the
  release URL, or vendored:

  ```sh
  runa sdk runtime --out build/runtime
  mkdir -p vendor && npm pack ./build/runtime --pack-destination vendor
  npm install ./vendor/futuruna-runtime-0.6.0.tgz
  ```

See [Answering an entry](../reference/calculations.md#answering-an-entry-1)
and [The runtime package](../reference/calculations.md#the-runtime-package).

## Fixed

- **`sort` on a partial case no longer panics.** In 0.5.0, a partial case
  whose sort key was unknown (a left-out `account_id` of an event sorted by
  account) could stop the call with "internal runtime failure during
  calculation": the comparator treated an unknown as equal to every value,
  which is not a total order, and Rust's sort panicked once the list was long
  enough. An unknown now orders before every known value and equal to other
  unknowns. The key is still read, so the sorted list is unknown and the key
  becomes a need. `sort_by`, `list_min` and `list_max` share the comparator.

## Compatibility

- `@ calculate` → `@ entry`: `runa fmt --migrate` rewrites it.
- `interview(|c| query e(c), partial, complete)` → `answer(e, partial,
  from_case(complete))`; `x.rounds` → `map(x.rounds, |r| r.paths)`;
  `x.result == v` → `x.outcome == Answered(result = v)`. `runa fmt --migrate`
  rewrites these and lists every other use of `interview` or `Interview` with
  its line.
- Every contract's schema id is `futuruna.entry.*` (was `futuruna.calculate.*`)
  and every schema hash changes. Regenerate templates and stored hashes; a 0.5
  input envelope with a 0.5 hash is refused as any stale hash is.
- Rust API: `PreparedCalculation` is `PreparedEntry`.
- Entry files are named `*.entry.runa` by convention, not `*.calculate.runa`;
  `runa` reads either name, so renaming is optional.
- TypeScript SDK: the pattern-keyed `resolve()` and `Resolvers`, the reply
  helpers `answer(need, value)` and `ask`, and `Resolution` are gone; answer
  with `<entry>Answer` and a `<Entry>Resolve`, replying `given(need, value)`
  or `open`. `runa sdk ts --runtime` and the generated `runtime.ts` are gone;
  install `@futuruna/runtime` at the version of the `runa` that generates the
  SDK. Regenerate every SDK.

## Known limitations

- `later` needs are not batched or answered until a round makes them needs.
- A unit cannot declare a rounding policy yet; generated converters refuse
  an amount finer than one unit.
- Replies are typed by what TypeScript sees; data that reaches
  `<entry>Answer` untyped or through a cast is checked only at run time.
- `@ field(at = pathof(…), label, help)`, the RFC's use-site label, is not in
  this release; a use-site label stays an `@ meta` record naming its field by
  `pathof`.
