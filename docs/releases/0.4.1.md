# Futuruna 0.4.1

## Every result carries the assumptions it rests on

`runa call` returns with every result the assumptions it rests on, explained
or not: `assumptions` beside `result` in each case, and inside `Complete` in a
`--partial` call. They are the `Assumption` attachments of the rule clauses
that fired in the case, of the sections those clauses sit in, and of the entry
and its section; each once (by binding and value), in the order the model
writes them (by file, then line), with its `section`, its `binding` and its
`value`. A case with none leaves `assumptions` out.

- **Writer.** Say each assumption once, on the rule it concerns: `@ meta(
  Assumption(value = ...))` on the exception that applies only on closing is
  listed only when that exception applied. A model no longer keeps a list of
  assumptions in its result type.
- **Reader.** Every listed assumption matters to this result; an assumption
  on a clause that did not fire is absent.
- **Format.** The explanation no longer has `assumptions`; it reads the same
  table of fired clauses the result's assumptions come from. `runa schema
  --format result` prints the JSON Schema of a case of `runa call`'s output;
  `--format partial-result` types `assumptions` in `Complete`. A result
  workbook lists them on an `assumptions` sheet.
- **SDK.** `<entry>(transport, input)` returns `{ result, assumptions }`
  (`Calculated<R>`, each a `CalculationAssumption`), `Complete` and a
  `resolve` loop's `Complete` carry `assumptions`, and `Explained<R>` is
  `{ result, assumptions, explanation }`. The WebAssembly engine's documents
  carry them as `runa call` does.
- **Cost.** Each case records the rule clauses that fire (one table lookup
  per clause that returns a value; no value is traced) and reads the
  attachments from the model's files once per worker. On the tax-service
  Aktiesparekonto cases the cases after the first run as fast as in 0.4.0;
  the first case of a worker pays the one-time read of the model's files
  (about 0.13 s there).
- **Fixed.** Two clauses of one rule with different `@ meta` attachments each
  report their own; before, both reported the first clause's.
