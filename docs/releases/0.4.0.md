# Futuruna 0.4.0

Futuruna 0.4.0 is in development; this file collects its release notes.
Everything new in this release is Experimental unless a section says
otherwise.

`runa call --explain` returns with every result where each amount came from:
the rule clause that produced it, the exception that applied, the law section
and the paragraphs the clause cites with their quoted text, and the rules and
inputs it was computed from.

## Explanations (Experimental)

- **`runa call --explain`.** Every case result gains `explanation.values`:
  each leaf of the result by its output path (the path syntax of needs), with
  `by` (the rule clause, the input path of a value passed on unchanged, a
  computation outside any rule, or a constant) and `from` (the nearest rules
  and inputs it was computed from, with their values, at most 32).
  `explanation.sections` holds each law section an explained clause sits in:
  its location, quoted documents, metadata attachments and quote.
- **`--explain=full`** lists every contributor and adds `derivation`, the
  whole tree of rule nodes behind the reported values.
- **Partial cases.** `runa call --partial --explain` explains every
  `Complete` result. `--explain` is refused with `--partial=check`, and
  writes JSON only.
- **Results unchanged.** A case's `result` is byte for byte the one
  `runa call` gives without `--explain`; the tax engine's cases and needs
  interviews are compared in both modes.
- **No cost when off.** Values carry provenance only in explained cases; an
  unexplained case creates no traced value (a test counts them).
- **`runa schema --format explanation`** prints the explanation's JSON
  Schema.

## Paragraph citations (Experimental)

- **`--@cite:§ 9, stk. 3--`** above a rule clause names the paragraphs it
  implements; several are separated by `;`, `nr. N` names an item and
  `in <source>` a quoted document. A citation on a rule's first clause covers
  its other clauses that have none.
- **Checked.** `runa check` finds each cited paragraph in the quote of the
  section around the clause (`§ N.`, `Stk. N.` and `N)` lines) and rejects a
  paragraph the quote does not hold, naming the paragraphs it does hold. A
  citation outside a law section or not above a rule clause is an error too.
- An explanation shows a cited paragraph's quoted text verbatim; a clause
  without a citation shows its section.

## Explanations in the WebAssembly engine and the TypeScript SDK (Experimental)

- `Model.callExplained(entry, input, full?)` and
  `Model.callPartialExplained(entry, input, full?)` return the documents of
  `runa call --explain` and `runa call --partial --explain`. Source locations
  are relative to the model root.
- `runa sdk ts` generates `<entry>Explained` and `<entry>QueryExplained`, the
  `Explanation` types, and the optional transport methods `callExplained` and
  `callPartialExplained`.

The design is [Explanations](../rfcs/explanations.md).

## Partial cases and needs (Experimental)

- **A need names the rule of the law it waits for.** `waiting_rule` is the
  innermost rule or function on the stack when the path was first read that
  is declared in a law section (one whose quote holds a `[sources/...]`
  document), else in any section with a quote, not the validation helper or the entry
  that happened to read it. Such a need also carries the `section` and the
  `paragraphs` cited on the clause being tried (an exception's own
  citation), on the rule's first clause, or on the function. Without a
  sectioned frame, `waiting_rule` is the innermost rule family, or the entry,
  as before.
- **Citations on functions.** `--@cite` may stand above a function
  (`> f(...)`) inside a section.
- `runa schema --format partial-result` and the TypeScript SDK's `Need` type
  gain the optional `section` and `paragraphs`.

## Compatibility

- **Runtime values.** The interpreter's `Value` gains a `Traced` variant; an
  exhaustive `match` on `Value` in Rust code using the library must cover it.
- **TypeScript SDK names.** `<entry>Explained`, `<entry>QueryExplained` and
  the explanation types are generated names; a contract type of the same name
  must be renamed to use the SDK.
- Output without `--explain` is unchanged: `explanation` is left out.
- **Needs.** `waiting_rule` may name a different, outer rule than before for a
  model with law sections; `section` and `paragraphs` are new optional
  fields. A client that keyed on the old `waiting_rule` must accept the new
  value; `runa call --partial` is Experimental.

## Known issues

- Explanations are an interpreter feature; compiled programs do not explain.
- A single value a rule returns unchanged from a deeper rule or the input is
  reported for the outer rule, with the deeper rule or the input in `from`.
