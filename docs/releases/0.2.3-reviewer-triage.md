# Futuruna 0.2.3 reviewer triage

This is the working review record for the external issue queue, beginning at
[issue #2](https://github.com/Futuruna/futuruna/issues/2). The initial queue on
2026-09-25 contains 120 open issues, #2 through #121. The target is Futuruna
0.2.3; this record is not a release announcement or evidence that the release
gates have passed.

Evaluate issues in number order against current source. Related defects may
need one coherent implementation, but each report needs its own reproduction
and disposition. Accept valid, high-value corrections; document unsupported
claims and design tradeoffs explicitly. The reviewer's
[root-cause map](https://github.com/Futuruna/futuruna/issues/121) helps locate
related code, but its proposed designs still require evaluation.

## User-directed database removal (#120)

The user explicitly selected the database portion of [#120](https://github.com/Futuruna/futuruna/issues/120)
ahead of the remaining numeric queue. Task `td-7a9606` removes `@ store`,
`@ persist`, migrations, fact mutation, database change feeds, and the six
`db_*` builtins. Review confirmed the builtins were native SQLite wrappers
with incomplete interpreter stubs, so merely moving them into the stdlib would
retain inconsistent execution. Host applications should own storage and pass
typed values into Futuruna; a future optional package is a separate design.

compiler metadata, SQL schema/migration/query generation, transaction/watch
machinery, automatic dependencies, editor entries, and active database-only
fixtures/demos. Retired syntax fails explicitly, including nested and manually
constructed annotation forms; unchecked embeddings no longer fabricate values
for the removed builtin names. Authored functions can still use those names.
Ordinary assertions, in-memory facts/queries, calculation contracts, scopes,
streams, effects, proof verification, and Explore's independent filesystem
journal remain in scope for preservation. The proof-kernel recommendation in
#120 is **not adopted**.

Historical research stays clearly marked at its existing paths. Removed demo
sources are linked to Git history. Existing database files are not touched.
The [compatibility guide](../compatibility-guides/0.2.x.md#database-feature-removal)
records the intentional source/behavior break and migration path. The storage
canary lane is retired with its implementation; new negative and positive
