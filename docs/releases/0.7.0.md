# Futuruna 0.7.0

Futuruna 0.7.0 adds **open keyed inputs**: the law asks for an entry whose key
it computes ("the account's balance on 20 February the year after"), and the
integrator gives the entries asked for, without guessing which keys to supply.
Everything new in this release is Experimental.

## Open collections (Experimental)

```runa
# Balance(@ field(key = True, label = "Day") day: String, @ field(label = "Value") value: Int)
# Account(delisted: String, @ field(label = "Balance", open = True) balances: List(Balance))

@ entry
> deemed(a: Account) -> Int {
    lookup(a.balances, a.delisted).value
}
```

- **`@ field(open = True)`** on a field of type `List(T)`, where `T` declares a
  key field (`@ field(key = True)`): the case never gives the collection whole.
  It may be left out (no entries given yet). `runa check` reports `open` on a
  type, on a field that is not a `List`, or of a type without a key field.
- **`lookup(list, key)`** is the entry whose key field is `key`: on an open
  field (written `lookup(record.field, key)`) the entry itself, on any other
  keyed list `Some(entry)` or `None`. Its key has the key field's type.
- **An entry the case does not give** is, in a partial case, a need at
  `balances[day="2027-02-20"]` (the key as JSON) with that key in `keys` and
  the field's metadata, answered with the whole entry; a complete call fails
  with an error naming the field and the key. A missing entry is fallible, so a
  partial case never completes past it.
- **No whole-collection reads.** Every read of an open field other than as
  `lookup`'s collection (`filter`, `map`, a loop, passing it on) is a check
  error: the case never holds all of it.
- **`fill`, `answer`, `from_case`** write an entry need by adding the entry.
- **TypeScript SDK.** The need's pattern is `balances[]`, its answer the
  element type: `given(need, { day, value })` adds the entry, and `setAt` sets
  the key from the path or refuses another. `[]` in a pattern stands for a
  list index or an entry key. The open field is optional in the input type and
  `balances` is no pattern.
- **Interpreter only.** `lookup` runs in the interpreter, as `query` does;
  `runa build` and `runa run` refuse it.

See [Open collections](../reference/calculations.md#open-collections) and the
RFC [Open keyed inputs](../rfcs/open-keyed-inputs.md).

## Compatibility

- `lookup` is a builtin: a program that declares its own `lookup` keeps it.
- A type with an open field has a new content hash; other hashes and schema
  fingerprints are unchanged (`open` is written only when true).
- The `@ field` label rule now reads "a `label`, or only the markers `key` and
  `open`".
- Need paths may hold `[field=value]` steps; a client that parses paths must
  read them (the runtime's `parsePath`, `pathPattern` and
  `matchesPathPattern` do).

## Known limitations

- An open collection has no answer "there is no entry"; model a day without a
  balance as an entry.
- A whole-record read (`show(case)`, `case == other`, a record pattern) still
  reads an open field as the case gives it.
- `pathof` cannot name an entry by key; tests compare entry needs by `keys`.
