# Futuruna 0.2.3

Futuruna 0.2.3 gives every program one meaning. The interpreter and compiled
code implement the same written reference, operations either return a value or
report a located error, and the analysis commands never run the model.

## Language

- **One reference semantics.** `docs/reference/` defines what a program means.
  The differential gate compares interpreter and compiled output, exit status
  and errors for every corpus program, the examples and generated programs; a
  compiled build failure is a failure.
- **Fail closed.** `parse_int`, `parse_float`, `read_file`, `json_parse`,
  `http_get` and `http_post` return `Result`. Failed writes, unhandled effect
  operations, rule misses, non-Bool conditions and predicates, Float division by
  zero, and ended streams are located errors in both execution modes.
- **A complete frontend checker** runs before interpretation, calculation and
  audit: Int and Float are distinct for parameters and fields, sum-type fields
  require every variant or a narrowed value, impls are checked against their
  trait signatures, exceptions need a base rule, `<-` needs a `Result` or
  `Option`, `String +` joins only scalar values, and prelude constructor and
  built-in type names are reserved.
- **Methods dispatch by receiver type.** Type-body and impl methods are not
  global functions; a declared function always wins a free call, and user
  definitions shadow builtins in both modes.
- **Deep recursion.** Recursion is limited by the real thread stack, not a
  fixed depth; unbounded recursion still fails with a located error.
- **Live streams and actors** are shared, synchronous references with one
  delivery order in both modes: subscribers see every later value, `complete`
  and `error` end a stream once, and actor messages are handled before `<-`
  returns.
- **One value order and display.** Numbers order numerically and text by code
  point for `sort`, Map and Set; `show` prints the same text in both modes.
  Float values cannot be Map keys or Set elements.
- **Danish source files** translate keywords and builtin names per file, after
  user declarations, so declared names keep their spelling across imports.
  `fortolk_heltal` and `fortolk_kommatal` read Danish number text.
- **Lexical rules.** `1_000` digit groups; date-shaped and comma-grouped
  numbers are errors; banners of four or more dashes are one block delimiter;
  an indented line starting with an operator never silently disappears; common
  syntax from other languages gets a hint naming the Futuruna form.
- **A smaller surface.** The proof kernel and explicit proof terms are gone;
  `runa verify` uses the SMT backend and states its guarantee in its output.

## Tools

- `runa check`, `emit`, `audit` and `call` never perform host effects:
  `@ comptime` and `@ calculate` are pure, audit does not run top-level
  statements, and `runa check --build-deps` is required before Cargo builds
  declared crates.
- Dependencies are pinned in `runa.lock`; only `runa add` and `runa fetch` use
  the network. The language server never clones or fetches.
- Build caches live in a private per-user directory.
- `runa check` maps generated-code failures back to the `.runa` source.
- `runa verify` follows imports; `runa audit` stops on unresolved imports; the
  language server follows imports for go-to-definition.
- Calculation templates mark every value to fill; `runa call` rejects an
  unfilled template.
- Each tool prints the guarantee it provides. Documentation examples, the
  formatter and `verify` are checked by oracles in the mint gate, and an
  issue-reproduction corpus guards against regressions.

## Installation

Use the checksummed binaries on the
[GitHub release](https://github.com/Futuruna/futuruna/releases/tag/v0.2.3), or
build the tag with
`cargo install --git https://github.com/Futuruna/futuruna --tag v0.2.3 --locked futuruna`.
