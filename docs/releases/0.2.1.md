# Futuruna 0.2.1

This release delivers the first validated batch of fixes from the external
review, together with the calculation and modeling improvements made since
0.2.0. Work on the remaining reports continues toward 0.2.3.

## Highlights

- Stronger error handling: integer overflow and zero divisors fail explicitly;
  invalid invariant predicates, return types, match coverage, lexical input,
  unknown effects, and imported function bodies receive frontend diagnostics.
- More dependable native builds: concurrent projects use isolated workspaces,
  cached binaries respect compiler identity, date-prefixed filenames work with
  Cargo-backed checks, and loop record fields retain their correct owner.
  Complete complementary rule guards, guarded helper calls, borrowed inputs,
  optional comparisons, collection values and program references inside lambdas
  receive additional native coverage.
- Better calculation inputs and reports: duplicate keys and independent input
  errors are diagnosed, workbook round trips preserve empty strings, and the
  Danish annual-assessment workflows retain stricter source validation and
  explicit unknowns. Report viewers preserve exact amounts and validity gates.
- More useful testing and verification: interpreted tests continue after a
  failed file and report a complete summary; native invariant failures retain
  their details; verification failures return failing exit codes.
- Editor and formatting improvements: positioned Unicode-aware diagnostics,
  record-field completion and hover, protocol fixes, richer syntax highlighting,
  documented editor installation, and formatting that preserves literal and
  quoted source contents.
- A smaller language core: built-in SQL and automatic persistence have been
  removed. Ordinary rules, effects, streams, scopes, Rust interop, and Explore's
  filesystem journals remain available.

## Upgrade notes

This release **removes `@ store`, `@ persist`, the `db_*` builtins, and their
associated database/migration commands**. Keep storage in the host application
through existing interop. See the complete
[database migration guidance](../compatibility-guides/0.2.x.md#database-feature-removal).
Existing database files are not deleted by this release.

Previously accepted invalid programs may now be rejected earlier. Regenerate
calculation templates when their contract fingerprint changes, then transfer
reviewed facts; do not edit a saved fingerprint to bypass a mismatch. Retain
older Explore evidence with its original source and compiler identity.

The 0.2.0 release binaries predate important calculation safeguards. Select the
new executable explicitly and run the
[tax-audit runtime check](../../website/public/ai-setup.md#tax-audit-runtime-check)
against the model checkout before calculations. This checks runtime
compatibility, not the correctness of a legal interpretation.

The [compatibility guide](../compatibility-guides/0.2.x.md) records the detailed
changes. The [reviewer triage](0.2.3-reviewer-triage.md) records remaining work;
0.2.1 does not claim that the entire review queue is resolved.

## Distribution

GitHub release assets cover Linux x86-64/ARM64 and macOS Intel/Apple Silicon,
with `SHA256SUMS`. The published release records the actual macOS signing and
notarization status. crates.io publication depends on configured credentials
and is reported separately from the GitHub binaries.
