# Futuruna 0.5.0

## Named scalar types (Experimental)

`# Isin: String "International Securities Identification Number" where
isin_shape, isin_check_digit` declares a type whose values are the Strings
that pass the checks. The writer says once what a kind of value is, what it
looks like and how it is asked for; the reader of `isin: Isin` can rely on the
type. See [Named scalar](../reference/runes.md#named-scalar) and
[the design](../rfcs/named-scalar-types-and-rule-result-types.md).

- **An account id is not an ISIN.** An `Isin` is accepted where a `String` is
  expected, also inside `List`, `Set`, `Option` and `Map`, but a plain
  `String` or an `AccountId` where an `Isin` is expected is a type error, and
  so is `map_contains(accounts, e.isin)` when `accounts` is keyed by
  `AccountId`. Any operator other than a comparison works on the primitive
  and gives the primitive, so `p.account_id + "/" + p.isin` is a `String` as
  before.
- **Values are checked where they are made.** A literal that takes a named
  scalar is checked by `runa check` (`= home: CountryCode = "dk"` is an
  error). `Isin(p)` stops on a value that fails a check; `parse(Isin, p)`
  gives `Result(Isin, String)`. `runa call` runs the checks on every input
  value of a named scalar type and reports a failure as an input diagnostic
  at its path, with the new members `scalar` and `check`. A check always
  runs the definition its name has in the file that declares the type.
- **Field metadata once.** `@ field(...)` before the declaration labels every
  input field that holds the type. A field's `@ field` that repeats it is an
  error, and `runa fmt --migrate` removes it; `@ field(key = True)` alone marks
  a key and keeps the type's label.
- **Contract and SDK.** `runa schema` marks a field `"scalar": "Isin"` and
  lists the named scalars with their checks. `runa sdk ts` declares
  `type Isin = string & { readonly __scalar: "Isin" }`, `IsinSchema` and the
  constructor `isin(text)`, and throws `CalculationError` of kind `input`
  with `scalar` and `check` when the engine refuses a value.
- **Erased everywhere else.** At runtime, on the wire, in `runa verify` and in
  generated Rust (`pub type Isin = String;`) a value is its primitive.
- **Proofs use the checks.** `runa verify` assumes each check of a named
  scalar input that translates to SMT, and a counterexample names a check it
  could not assume. `Isin(p)` in a verified body is an obligation: the checks
  must hold for `p`, and where one does not translate the claim is
  unsupported, never proved.
- **Templates refuse what calls refuse.** `runa template --input` runs the
  same checks as `runa call` on the values it carries over.

## Compatibility

Additive: a program without named scalars checks, runs and produces the same
contract as before. `runa call` diagnostics and contracts gain optional
members only where a program declares a named scalar.
