# Futuruna 0.5.0

Futuruna 0.5.0 is in development; this file collects its release notes.
Everything new in this release is Experimental unless a section says
otherwise.

A test can now state an interview in Futuruna: the case from the model's own
builders with `unknown` where a fact is not known yet, the question as
`query entry(case)`, and the expected rounds as checked paths. Every query a
test asks also runs the strict-mode oracle and the completion test.

## Needs in the language (Experimental)

- **`unknown`** is a value not known yet. It takes the type of its place, as
  a number literal takes its unit: an argument, a field value, a list
  element, a typed binding, a declared result, a branch. It means what a
  left-out field means in a partial JSON case: `unknown` for an optional,
  scalar or list is one unknown; for a record, the record exists with each
  field unknown; for a sum type, the variant is unknown. `Some(unknown)` of a
  record says "present, nothing known yet". `unknown` is never read: as an
  operand, a side of `==`, a condition, a scrutinee or the argument of a
  builtin such as `show` it is a check error, and a builder that reads one
  before a query stops with an error naming the `unknown`'s line.
- **`query entry(case)`** asks a calculation entry (`@ calculate`) about a
  case and returns `Query(o, i) = Complete(result: o, unused: List(Path(i))) |
  Needs(needs: List(Need(i)))`. It runs the entry as `runa call --partial`
  does, on the entry's own checked program. `query` is a contextual keyword:
  only `query name(...)` is a query.
- **`Need(i)`** carries the need's path, kind (`FactNeed` or `EntryNeed`),
  keys, entry and subject, label, question, help, unit, sources and who waits
  (`waiting: List(NeedWaiting)`, each with its `rule`, `section` as a
  `ProgramReference` and cited paragraphs). Its members are declared from the
  same Rust table the partial-result JSON and `runa schema --format
  partial-result` are tested against.
- **Typed paths.** `Path(i)` is a path into a value of type `i`.
  `pathof(T::...)` is a `Path(T)` where a path is expected and a `String`
  elsewhere, as before. `pathof` takes list indices (`TaxCase::accounts[1]::closing_cash_ore`).
  A path rooted at another type than the one it is compared with is a check
  error. A path names the alternative of a sum type it passes through
  (`taxpayer.outside_endavu.OutsideDeclared.other_share_income_ore`), as
  field metadata does.
- **`fill(partial, complete, paths)`** answers needs from a complete case: a
  record as existing with its fields unknown, a variant by its tag, every
  other value (and a `Date`) whole. **`interview(ask, partial, complete)`**
  asks until the case is complete and returns `Interview(rounds, result)`.
- **Tests run the guarantee.** Under `runa test` every query also runs the
  strict-mode oracle and the completion test; a violation fails the test at
  the query's line, naming the round and the completion that disproves it.
  Outside tests a query propagates only.
- **No calculation reaches a query.** `runa check` reports a `query` or
  `unknown` that any `@ calculate` entry can reach, with the call chain.
- **Interpreter only.** `runa build` and `runa run` report each `query` and
  `unknown` as an error; `runa check` of such a program checks the frontend
  and reports `interpreted (query)`; `runa test --run` runs a test that asks
  a query in the interpreter and marks it `interpreted (query)`.

### Migration

- `unknown` is a reserved word; a binding, parameter or function named
  `unknown` is a parse error. `runa fmt --migrate` renames it to `unknown_`.

See `docs/rfcs/needs-in-the-language.md`.
