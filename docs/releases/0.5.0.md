# Futuruna 0.5.0

Futuruna 0.5.0 is in development; this file collects its release notes.
Everything new in this release is Experimental unless a section says
otherwise.

A test can now state an interview in Futuruna: the case from the model's own
builders with `unknown` where a fact is not known yet, the question as
`query entry(case)`, and the expected rounds as checked paths. Every query a
test asks also runs the strict-mode oracle and the completion test.

## Needs in the language (Experimental)

- **`unknown`** is a value not known yet. It takes the type of its place, as
  a number literal takes its unit: an argument, a field value, a list
  element, a typed binding, a declared result, a branch. It means what a
  left-out field means in a partial JSON case: `unknown` for an optional,
  scalar or list is one unknown; for a record, the record exists with each
  field unknown; for a sum type, the variant is unknown. `Some(unknown)` of a
  record says "present, nothing known yet". `unknown` is never read: as an
  operand, a side of `==`, a condition, a scrutinee or the argument of a
  builtin such as `show` it is a check error, and a builder that reads one
  before a query stops with an error naming the `unknown`'s line.
- **`query entry(case)`** asks a calculation entry (`@ calculate`) about a
  case and returns `Query(o, i) = Complete(result: o, unused: List(Path(i)),
  assumptions: List(QueryAssumption)) | Needs(needs: List(Need(i)))`. It runs
  the entry as `runa call --partial` does, on the entry's own checked
  program. `query` is a contextual keyword: only `query name(...)` is a query.
- **A `Complete` carries its assumptions** as `runa call` does since 0.4.1:
  each `QueryAssumption` has `section`, `rule` and `binding` as
  `Option(ProgramReference)`, so a test names the assumption a case rests on
  with `refof(...)`, and the check rejects a name that does not exist.
- **Assumptions name the section and the rule apart** (in `runa call`, the
  SDK and the workbook too): `section` is the law section an assumption is
  written in and `rule` the rule, member or function it is written on, each
  left out when it does not apply. Before, one `section` string held the
  section or, outside any section, the rule's name, so a reader could not
  tell which.
- **`Need(i)`** carries the need's path, kind (`FactNeed` or `EntryNeed`),
  keys, entry and subject, label, question, help, unit, sources and who waits
  (`waiting: List(NeedWaiting)`, each with its `rule`, `section` as a
  `ProgramReference` and cited paragraphs). Its members are declared from the
  same Rust table the partial-result JSON and `runa schema --format
  partial-result` are tested against.
- **Typed paths.** `Path(i)` is a path into a value of type `i`.
  `pathof(T::...)` is a `Path(T)` where a path is expected and a `String`
  elsewhere, as before. `pathof` takes list indices (`TaxCase::accounts[1]::closing_cash_ore`).
  A path rooted at another type than the one it is compared with is a check
  error. A path names the alternative of a sum type it passes through
  (`taxpayer.outside_endavu.OutsideDeclared.other_share_income_ore`), as
  field metadata does.
- **`fill(partial, complete, paths)`** answers needs from a complete case: a
  record as existing with its fields unknown, a variant by its tag, every
  other value (and a `Date`) whole. **`interview(ask, partial, complete)`**
  asks until the case is complete and returns `Interview(rounds, result)`.
- **Tests run the guarantee.** Under `runa test` every query also runs the
  strict-mode oracle and the completion test; a violation fails the test at
  the query's line, as `file:line: query entry, round N: ...`, naming the
  completion that disproves it. Outside tests a query propagates only.
  `runa test`'s `guarantee:` line says so.
- **No calculation reaches a query.** `runa check` reports a `query` or
  `unknown` that any `@ calculate` entry can reach, with the call chain. A
  parameter, lambda parameter, match pattern or block binding named like a
  top-level binding is the local name, so a test may name its query `closed`
  while a rule has a parameter `closed`.
- **Interpreter only.** `runa build` and `runa run` report each `query` and
  `unknown` as an error; `runa check` of such a program checks the frontend
  and reports `interpreted (query)`; `runa test --run` runs a test that asks
  a query in the interpreter and marks it `interpreted (query)`.
- **Sections across files.** `refof(section name)` names a section of the
  file it stands in or of a file it imports, so a test compares a need's
  waiting section with `Some(refof(section share_income))`. A name two files
  declare is a check error naming both.
- **Typed entry metadata.** A field another calculation provides writes
  `entry = refof(share_income)` and `subject =
  pathof(TaxCase::taxpayer::spouse)` (in a field record, `entry:
  ProgramReference?`). `runa check` reports, naming the field, an `entry`
  that is not an `@ calculate` entry, a subject rooted at another type than
  the calculation's input or holding another type than the entry takes, and
  a field whose type is not the entry's result type. The contract's
  `provided_by` keeps the same strings.

The reference is the *Needs in the language* section of
`docs/reference/calculations.md`; the design is
`docs/rfcs/needs-in-the-language.md`.

### Migration

- `unknown` is a reserved word; a binding, parameter or function named
  `unknown` is a parse error. `runa fmt --migrate` renames it to `unknown_`.
- `runa fmt --migrate` rewrites string `entry`/`subject` field metadata as
  `refof`/`pathof` when exactly one calculation input reaches the field, and
  lists the others as `file:line` with the reason. The string forms are still
  read, with the same checks.

## Bindings named like a function or rule

- A top-level binding may take the name of a rule, as before (`= tax = tax(case)`):
  `tax` reads the binding and `tax(...)` calls the rule, unless the binding
  holds a function, which takes the calls after it. A function now behaves
  the same; before, `runa check` passed and the interpreter called the
  binding's value and stopped with "value is not callable".
- Each such top-level binding is reported with a warning naming the
  binding, the function or rule and where it is declared, and what each use
  means. A warning does not fail the command. Bindings in a body and
  parameters are lexical and are not reported: they hide a function or rule
  of their name in their scope, so calling one that holds no function is a
  check error naming the hidden function.

## Named scalar types (Experimental)

`# Isin: String "International Securities Identification Number" where
isin_shape, isin_check_digit` declares a type whose values are the Strings
that pass the checks. The writer says once what a kind of value is, what it
looks like and how it is asked for; the reader of `isin: Isin` can rely on the
type. See [Named scalar](../reference/runes.md#named-scalar) and
[the design](../rfcs/named-scalar-types-and-rule-result-types.md).

- **An account id is not an ISIN.** An `Isin` is accepted where a `String` is
  expected, also inside `List`, `Set`, `Option` and `Map`, but a plain
  `String` or an `AccountId` where an `Isin` is expected is a type error, and
  so is `map_contains(accounts, e.isin)` when `accounts` is keyed by
  `AccountId`. Any operator other than a comparison works on the primitive
  and gives the primitive, so `p.account_id + "/" + p.isin` is a `String` as
  before.
- **Values are checked where they are made.** A literal that takes a named
  scalar is checked by `runa check` (`= home: CountryCode = "dk"` is an
  error). `Isin(p)` stops on a value that fails a check; `parse(Isin, p)`
  gives `Result(Isin, String)`. `runa call` runs the checks on every input
  value of a named scalar type and reports a failure as an input diagnostic
  at its path, with the new members `scalar` and `check`. A check always
  runs the definition its name has in the file that declares the type.
- **Field metadata once.** `@ field(...)` before the declaration labels every
  input field that holds the type. A field's `@ field` that repeats it is an
  error, and `runa fmt --migrate` removes it; `@ field(key = True)` alone marks
  a key and keeps the type's label.
- **Contract and SDK.** `runa schema` marks a field `"scalar": "Isin"` and
  lists the named scalars with their checks. `runa sdk ts` declares
  `type Isin = string & { readonly __scalar: "Isin" }`, `IsinSchema` and the
  constructor `isin(text)`, and throws `CalculationError` of kind `input`
  with `scalar` and `check` when the engine refuses a value.
- **Erased everywhere else.** At runtime, on the wire, in `runa verify` and in
  generated Rust (`pub type Isin = String;`) a value is its primitive.
- **Proofs use the checks.** `runa verify` assumes each check of a named
  scalar input that translates to SMT, and a counterexample names a check it
  could not assume. `Isin(p)` in a verified body is an obligation: the checks
  must hold for `p`, and where one does not translate the claim is
  unsupported, never proved.
- **Templates refuse what calls refuse.** `runa template --input` runs the
  same checks as `runa call` on the values it carries over.

### Compatibility

Additive: a program without named scalars checks, runs and produces the same
contract as before. `runa call` diagnostics and contracts gain optional
members only where a program declares a named scalar.
